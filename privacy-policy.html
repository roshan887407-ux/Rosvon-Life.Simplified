This Privacy Policy describes how Roshan Sharma ("Developer", "we", "us", or "our") handles information when you use the Rosvon Android application ("App" or "Service"). It distinguishes local storage, Google Drive backup, Firebase/Google Cloud processing, community visibility, AI processing, diagnostics, advertising, and billing.

1. Information We Collect

1.1 Information You Provide Directly

  • Account Information: Google Sign-In provides a Firebase user ID, email address, and display name. Firebase records can also include account creation/update timestamps, backup-setup state, game Health/HP, entitlements, and purchase-verification information. Rosvon does not retrieve your Google password and does not automatically store your Google profile picture. Guest mode is available without a Rosvon cloud account.
  • Community Profile: Signing in currently creates a community profile with a username, display name, bio, profile-photo URL, XP, level, rank, achievement identifiers/count, and a privacy flag. The profile is public by default. Privacy mode hides statistics in the current client but may leave the name, bio, and profile photo visible to signed-in users.
  • Profile Photo: A photo you select is copied to app-private local storage and may be included in Drive backup. If you are signed in, the current App also uploads a compressed copy to Firebase Storage and links it to your community profile without a separate "Go Public" step. Profile images can be read by signed-in community users.
  • Core User Content: Tasks, habits, journals, notes, projects, areas, resources, and Protocol settings/history are stored locally by default. Supported records and media are copied to your Drive App Data folder only after backup setup. Full records are not stored in the community database, but selected task, habit, project, and focus context may be sent to AI when the corresponding AI controls are enabled.
  • AI Chat and Memory: Chat messages and learned memory summaries are stored locally. An AI request can contain your message, recent chat, enabled app context, and identity/coaching-profile fields. After a response, Rosvon may make a second cloud request containing the raw user message and up to 500 characters of the AI response to decide whether to save a local memory.

1.2 Information Collected Automatically

  • Analytics Data: Firebase Analytics is included in the release App and may collect automatic app, session, device, and pseudonymous installation events. The audited code does not set a Firebase Analytics user ID and does not contain explicit per-screen Analytics logging. Exact retention is controlled in the Firebase/Google Analytics console.
  • Crash and Performance Data: Firebase Crashlytics, Performance Monitoring, and Sessions may process pseudonymous installation identifiers, device/app details, stack traces, diagnostics, and performance measurements. AI performance traces record metadata such as request/response length, timing, and result status; the audited trace code does not attach prompt text.
  • Advertising Data: Google Mobile Ads is loaded for penalty-display and opt-in rewarded-ad flows. The current App uses Google's sample/test application and ad-unit identifiers, so it does not currently serve production monetized inventory. Ordinary ad requests are used; the App does not currently implement Google UMP consent collection or enforce non-personalized requests. Google SDKs may process advertising/device identifiers, IP-derived coarse location, device information, impressions, clicks, and fraud/security signals under Google's terms.
  • Purchase and Credit Records: Google Play processes purchase details. Firebase Functions/Firestore store purchase tokens or hashes, product/entitlement state, request/event identifiers, user ID, quantities/amounts, and timestamps for verification, AI-credit consumption, and Golden Key redemption.

1.3 Information Accessed On-Device Only (Never Collected)

The following raw Protocol data is processed locally and is not serialized to Rosvon's cloud services by the audited code:

  • App Usage Statistics: If you grant Usage Access, Rosvon reads app screen-time totals and package names to show usage patterns, app limits, calendar insights, and top apps. Raw Usage Access events, package names, app limits, and blocked-app lists stay on your device. If AI Focus Context is enabled, selected focus-session summaries—not raw Usage Access events or package lists—may be sent to Google AI.
  • Accessibility Service Events: If you enable the Rosvon Protocol Accessibility Service, Rosvon receives Android window-change events and the package name of the app currently opened. Rosvon uses this only to show the breathing intervention screen when a user-defined app limit, daily limit, or focus-session whitelist rule is reached. Rosvon does not read screen text, messages, passwords, form fields, notifications, or web content, and does not perform gestures, clicks, or control actions in other apps.

5. AI Features and Data Processing

Rosvon includes an AI assistant called "Aria". AI requests are cloud requests. In the current version, the master AI-content switch and individual context categories are enabled by default; change them before sending a message if you do not want a category attached.

5.1 Firebase AI Logic / Agent Platform Gemini Processing

Aria sends requests through Firebase AI Logic to Google's Agent Platform Gemini service (formerly described as Vertex AI). A request can contain your message, recent chat, locally learned memories, enabled tasks/habits/projects/resources/focus summaries, and profile or runtime context such as name, age, personality/coaching fields, current screen, time, battery/offline state, streak, discipline, burnout, and mood. Google processes requests under the applicable Firebase, Google Cloud, and Gemini terms, project configuration, and retention practices. The App cannot verify or guarantee zero provider retention or model-training use.

5.2 AI Privacy Controls

You can disable app-data categories via Aria → three-dot menu → Privacy. Notes are separately controlled from Journal and Reflection entries, and project resource links follow Tasks & Projects. Turning off the master content control blocks new live app content and runtime context; it does not erase recent chat or learned memories, and your typed message is still sent when you request a response. Rosvon may make a second AI request using the raw user message and up to 500 characters of the response to decide whether to save a local memory. Aria does not receive raw Usage Access events, screen-time totals, individual package names, app limits, or blocked-app lists. If Focus Context is enabled, selected recent or active focus-session summaries may be attached.

6. Data Storage and Security

6.1 Local Storage

Local data uses Room (SQLite), DataStore, SharedPreferences, and app-private files/cache. Android's app sandbox limits ordinary access by other apps. Rosvon does not add SQLCipher or another app-layer encryption scheme to its Room database, preferences, or local media.

6.2 Cloud Storage (Opt-In)

Signing in activates Firebase account/community/game services. Google Drive backup is a separate optional feature:

  • Firebase/Google Cloud: A signed-in account can store authentication/account fields, timestamps, backup status, game Health/HP, community profile/statistics, profile photos, entitlements, purchase verification, AI-credit consumption, and Golden Key redemption records. The community profile is currently created public by default.
  • Google Drive App Data Folder: After backup setup, Rosvon writes supported tasks, habits, journals, notes, projects, profile/game state, preferences, and selected media as App Data backup files. AI chat/memories and some Protocol focus history are not included. The folder is accessible to Rosvon through your Google authorization and to Google as service provider; it is not exposed as an ordinary Drive file or copied to Rosvon's Firebase database.

6.3 Security Measures

  • Rosvon uses Google Sign-In through Credential Manager and Firebase Authentication. The App does not receive or store your Google password.
  • The audited Google/Firebase and custom network integrations use HTTPS/TLS; no custom cleartext endpoint was found.
  • Firestore rules restrict private user collections to the owner and configured administrators. Community profiles and profile images are readable by signed-in users.
  • The App integrates Firebase App Check with Play Integrity. Enforcement for each Firebase service is configured outside the App and cannot be confirmed by the source code alone.
  • Google-hosted services apply their platform storage protections. This is separate from local/Drive app-layer encryption, which Rosvon does not currently add.
  • We implement reasonable technical and organizational security measures to protect your data. However, no method of electronic storage or internet transmission is 100% secure, and we cannot guarantee absolute security.

7. Advertising

Rosvon includes Google Mobile Ads for penalty-display and user-initiated rewarded-ad flows. The current App uses Google's sample/test application and ad-unit identifiers and therefore does not currently serve production monetized inventory. If an ad request is made, Google's SDK may process:

  • Device advertising identifier (Google Advertising ID)
  • Device information (model, OS version)
  • IP address (for geographic ad targeting at a broad level)
  • Ad interaction data (impressions, clicks)

Rosvon does not attach journal text, tasks, habits, projects, raw screen-time records, app-limit lists, or focus history to an ad request. The current App makes ordinary Google ad requests and does not implement Google UMP consent collection, a privacy-options entry point, or an application-level guarantee that requests are non-personalized. Production ads must not be enabled in regions requiring consent until those controls are implemented.

Google's processing and device-level ad controls are described in Google's Privacy Policy. Device settings do not replace any consent flow the App is legally required to provide.

9. Data Retention and Account Deletion

  • Local Data: Rosvon app-private records remain until removed with an app control, Android's clear-data action, a successful in-app account-deletion flow, or uninstall. Provider-held records are separate.
  • Firebase/Auth/Storage Data: The in-app deletion flow attempts to delete Auth, user_info, user_data, community profile, profile pictures, Play purchase-token records, and challenge records. It is network/provider dependent and may require retry or support.
  • Current Backend Exception: The current deletion Function does not automatically delete the top-level ai_credit_consumptions and golden_key_redemptions records. Those records can contain Firebase user ID, request/event identifiers, quantities or amounts, product/reward context, and timestamps. The current code defines no automatic expiry period for them. This implementation should be corrected before publication.
  • Email Requests: You may ask for server-account deletion at rosvon.support@gmail.com. Email cannot remove app-private data from your phone or files in your Drive account. No fixed acknowledgement or completion time is guaranteed by the App.
  • Google Drive Backups: The in-app flow attempts deletion only when local backup/sync markers identify a Rosvon backup. Network, authorization, provider failure, or lost local markers can leave Drive App Data files behind; use Google Account controls or contact support if the App cannot remove them.
  • Analytics, Crash, Performance, Ads, Billing, and Platform Data: Retention is controlled by Google/Firebase console configuration, provider terms, and legal requirements. Rosvon source code cannot guarantee a 14-month or 90-day period or that every provider record is anonymous.
  • AI Data: Chat and memory summaries remain locally until cleared with available controls, successful deletion, clear-data, or uninstall. Google handles cloud request data under the applicable Firebase/Cloud/Gemini terms and project configuration; Rosvon does not guarantee zero provider retention.
